## Заголовки запроса

Можно разделить на типа:
### Авторизация и аутентификация

`Authorization `
`Cookie`

### Типы данных

`Content-type` - указывает какой тип данных в теле запроса (не указывать без тела)
`Accept` - указывает какие типы данных клиент принимает
`Accept-encoding` - указывает какой тип сжатия поддерживает (gzip, deflate ...). Сервер выбирает из списка от клиента метод сжатия и указывает его в заголовке `Content-Encoding ` ответа 
`Accept-language` - язык, который предпочитает клиент

### Кеширование

`Cache-Control` (public, private, `max-age=<int>`, no-cache, must-revalidate (когда устаревает age нужно переспросить у сервера)) - основной заголовок, который управляет кэширование.

`public` - Ответ можно кэшировать даже прокси/CDN (даже если содержит аутентификацию).
`private` - Только конечный клиент (браузер) может кэшировать; прокси — нет.
`max-age=<секунды>` - Максимальное время (в секундах), в течение которого ответ считается «свежим».
`s-maxage=<секунды>`- То же, что max-age, но только для общих кэшей (CDN, прокси). Игнорируется браузерами.
`no-cache` - Ответ можно кэшировать, но перед использованием нужно проверить актуальность у сервера (If-None-Match / If-Modified-Since).
`no-store` - Никогда не кэшировать — ни браузер, ни прокси. Используется для конфиденциальных данных.
`must-revalidate` - После истечения max-age обязательно проверить свежесть у сервера (не использовать «устаревший» кэш).

`If-Modified-Sinc` и `If-None-Match` - заголовки, которыми клиент проверяет статус ресурса с момента последнего обращения. (304 - если ресурс не изменился). Работают в паре с заголовком ответа `Last-Modified` . Этот заголовок отправляет когда менялся ресурс. Браузер в следующий раз возьмет эта данные и отправит серверу. Если все ок то 304, а если изменился то 200 и новые данные. 
`If-None-Match` - работает в паре с заголовком ответа `ETag`, который присылает идентификатор ресурса. Далее клиент отправляет его и сервер уже отправит либо 304 либо 200 и новый ресурс.

Для даннических данных (например состояния счета клиента банка) лучше ETag потому что он вычисляется при каждом изменении ресурса в отличии от `Last-Modified` (сложно отслеживать изменения).

### Безопасность

`Origin` - клиент указывает источник запроса, чтобы сервер проверил доверяет он ему или нет. Браузер сам его добавляет.
`Referer` - указывает url предыдущей страницы. 
`User-Agent` - Информация о клиенте
